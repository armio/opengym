# Shared fixtures

Test vectors that the Dart engine (`app/lib/engine`) and the Worker (`cloudflare/src/engine`,
`cloudflare/src/coach`) must both pass. They pin the two ports to the original openGym code and to
the fixes in [ARCHITECTURE.md](../ARCHITECTURE.md) §2.3 and §5.3.

| File | What it pins | Consumers |
|---|---|---|
| `engine/history.json` | `history.js`: modes, effort scale, last entry, best weight, schedule, set building, supersets | Dart all groups; Worker `shared` groups |
| `engine/progression.json` | `progression.js`: sessions, stalls, policies, increments, next prescription | both |
| `engine/onerm.json` | `onerm.js`: e1RM estimates, best set, series, records | both |
| `engine/effort.json` | `effort.js`: RIR/RPE, summaries, weekly averages, histogram | both |
| `engine/muscles.json` | `muscles.js`: muscle credit, load, levels, ranking | both |
| `engine/dates.json` | ISO week keys, streaks, workout order, duration/seconds formatting | both (formatting: Dart) |
| `engine/stats.json` | the Stats heatmap levels (engine.md §8.3) | Dart |
| `plan-hash.json` | `canonicalPlan` + `hashPlan` (coach.md §7.1, contract §5.4) | both |
| `current-value.json` | `currentValue` (coach.md §7.2), the basis of staleness | both |
| `validate.json` | `validatePlan` / `validateReview` of the original (coach.md §6) | Worker |
| `validate-port.json` | the port rules of contract §5.3 | Worker |

## Where the values come from

Everything except `validate-port.json` is **generated by running the original code**:

```sh
node docs/flutter-cloudflare/fixtures/tools/generate.mjs
```

`tools/harness.mjs` copies `frontend/src/lib/*.js` into a temporary directory (stubbing only
`i18n.js` and the media URLs), pins the clock and time zone, and loads the modules once as they
are, once per fix, and once with every fix applied. Each fix is a literal source patch of the
rule stated in the contract, so the "fixed" behaviour is also computed, not typed in. For every
vector:

- `expected` is what the fully fixed code returns;
- when that differs from the untouched original, the vector also has `original` (what openGym
  returns) and `fix` (the id of every fix that changes it on its own);
- the generator fails if a vector's result disagrees with the golden values of the specs'
  tables, or if a fix changes a vector that does not declare it.

A few groups have no original to run: `doubleStallCount` (engine-Q1), `sortWorkouts`
(engine-Q6/Q7), `linkSuperset` (coach-B3) and `heatmap` (lives in a React component). Their
values are written by hand and checked against a small reference implementation in the tools.
`validate.json` runs `api/coach/validate.js` and `plan-hash.json` runs the server's
`canonicalPlan` with the client's `hashPlan` (and checks that the client agrees).
`validate-port.json` is maintained by hand.

## Format of `engine/*.json`

```jsonc
{
  "about": "…",
  "clock": { "now": 1790755200000, "tz": "Europe/Madrid", "today": "2026-09-30" },  // when needed
  "constants": { "POLICIES": [ … ], … },       // module constants, to compare with yours
  "groups": {
    "<function>": {
      "scope": "shared" | "app",               // app: only the Flutter engine implements it
      "note": "…",                             // how to call it, when not obvious
      "fix": "engine-Q1",                      // the whole group exists because of a fix
      "vectors": [
        { "name": "…", "ref": "§10.5 #2",       // spec section the case comes from
          "args": { … },                       // named arguments, see below
          "now": 1799000000000,                // optional: replaces clock.now for this vector
          "expected": …,
          "fix": "critic-G3" | ["…"],          // optional: amended by these fixes …
          "original": …,                       // … and this is what openGym returns
          "sameInstance": true }               // applyPrescription only
      ]
    }
  }
}
```

**Comparison.** Deep equality. A key that is absent from `expected` must be absent (or
null/undefined) in the result. Numbers are the exact doubles the reference computed (for example
`1.2000000000000002`, `2.857142857142857`); a port that reorders floating-point operations may
compare with a 1e-9 tolerance. Key order never matters.

**JavaScript values JSON cannot hold** appear as marker objects:
`{"$js": "undefined"}`, `{"$js": "NaN"}`, `{"$js": "Infinity"}`, `{"$js": "-Infinity"}`. In Dart,
read `undefined` as `null`. They occur only where the original tests feed such inputs
(`estimate1RM`, `fmtSec`, `stepEffort`, `capEffort`, `modeOf`, `policyFor`).

**Exercises.** Ids are real catalogue ids: `0001` (3/4 sit-up, waist, the tests' `LIFT`), `1512`
(upper legs, `HEAVY`), `3220` (cardio, `CARDIO`), `0025` bench press, `0043` barbell full squat,
`0007` (back, cable). The catalogue a vector sees is the library plus the custom exercises in
`args.customEx` or `args.state.customEx`. Ids that do not exist (`'bench'`, `'nope'`) are
deliberate.

**States.** `args.state` is the subset of the original state `S` the function reads: `unit`,
`workouts`, `exWeights`, `customEx`, and for effort `effort`/`showRir`. In the port these come
from the settings doc, the workout rows, the `ex_weights` rows and the plan doc.

**Order.** Engine functions read `workouts` in the order given, and every vector gives them in
`(d, start)` order. Establish that order once with `sortWorkouts` (dates.json): stable, by `d`,
then by `start`, a workout without `start` counting as local noon of `d` in `clock.tz`.

**Clock.** Functions that read the clock in the original take `now` and the zone explicitly in
the port. Effort windows count back from `now`; `streakWeeks` starts from today's local date
in `tz`; `effortWeeks` reports `t` as local noon (epoch ms in `tz`) of each week's Monday.

### Fixes pinned here

| Fix | Rule | Vectors |
|---|---|---|
| engine-Q1 | double progression: a miss is a stall only if it did not improve on the previous session at the same weight | `doubleStallCount`; `nextPrescription` "double: climbing inside the range is not a stall" |
| engine-Q2 | the timed deload steps by the increment | `nextPrescription` "time: the deload step follows inc" |
| engine-Q5 | load records count reps-mode entries only | `bestWeightFor` |
| engine-Q6/Q7 | order by `(d, start)`; a date-only workout is at local noon | `sortWorkouts`; `effortSummary` and `effortWeeks` "date-only" vectors |
| critic-G3 | a plan target that differs from the last stored target starts a new baseline | `nextPrescription` "target changed: …"; `buildSets` "plan … changed" |
| coach-B3 | unique superset tag per link, `cleanupSg` after linking | `linkSuperset` |

`why` values are the original English i18n keys; critic-G3 adds
`'Plan target changed — this session sets the new baseline.'`.

## `plan-hash.json`

`vectors[]` of `{name, plan, canonical, canon, hash}`: `plan` is a plan doc (`routines`, `week`,
`customEx`), `canonical` is `canonicalPlan(plan)`, `canon` the exact string the hash iterates
over (UTF-16 code units, `JSON.stringify` escaping, numbers joined the way JavaScript prints them:
`1e+21`, `0.30000000000000004`, `1.5e-7`), `hash` the 16 hex digits. The first seven are the
golden vectors of coach.md §7.1.

## `current-value.json`

`{plan, vectors: [{name, change, expected}]}`: `currentValue(plan, change)`;
`{"$js": "undefined"}` for the structural change types.

## `validate.json`

`plan` (the fixture plan of coach.md §6.4), `constants.CHANGE_TYPES`, and two groups:
`validatePlan` with `args: {data, ctx?}` and `validateReview` with `args: {data}` (always against
`plan`). `expected` is the original's complete result, errors in order. The `extractJSON` cases of
§6.4 are left out: MCP tools receive structured input, so it is not ported.

## `validate-port.json`

`context` (the owner's custom exercises, athlete profile and working weights), `plan` (the
current plan doc) and three groups: `validatePlanProposal` (`args: {input, context?}`),
`validateChangesProposal` (`args: {input, context?}`, always against `plan`) and `clampEmoji`
(`args: {value}`). `expected` is matched partially: listed keys must match recursively, arrays
must have exactly the listed length, `errors` are exact and ordered. Each vector names the
`rules` it exercises.
